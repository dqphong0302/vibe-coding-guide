Chuẩn Bị Workspace & Kho Mã Nguồn Chuẩn Cho AI

Kho mã nguồn tốt cho con người cũng là kho mã nguồn tốt nhất cho AI Agent hiểu ngữ cảnh.

Mục tiêu chương: Tổ chức cây thư mục chuẩn cho AI Agent quét nhanh; thiết lập bộ hồ sơ quy tắc dự án (AGENTS.md, SPEC.md, RULES.md, .gitignore); nắm vững kỷ luật Git an toàn và nguyên tắc bảo mật Zero Secret Leakage.

1. Cấu trúc thư mục tối ưu cho AI Agent

AI Agent đọc hiểu thư mục rất nhanh nếu bạn đặt tên tệp có ý nghĩa, tránh nhồi nhét mọi thứ vào 1 file duy nhất nhưng cũng không chia tách quá vụn vặt:

CẤU TRÚC WORKSPACE TIÊU CHUẨN
my-project/
├── .gitignore          # Chặn commit file rác và bí mật (.env, node_modules, tmp/)
├── AGENTS.md           # Quy tắc hành vi & phong cách viết mã cho AI Agent
├── SPEC.md             # Tài liệu đặc tả yêu cầu kỹ thuật & tiêu chí nghiệm thu
├── index.html          # Trang chủ ứng dụng (HTML ngữ nghĩa, sạch sẽ)
├── css/
│   ├── style.css       # Design tokens, reset, biến màu sắc & font chữ
│   └── components.css  # Giao diện các thành phần chi tiết
├── js/
│   ├── app.js          # Logic điều phối chính & routing
│   └── modules/        # Các module xử lý dữ liệu và API
├── data/
│   └── sample.json     # Dữ liệu mẫu phục vụ kiểm thử
└── tests/              # Kịch bản kiểm thử tự động

1.1. Chụp “baseline” trước khi giao Agent sửa mã

Đừng bắt đầu bằng yêu cầu “sửa hết đi”. Trước mỗi thay đổi đáng kể, hãy ghi nhận trạng thái đang chạy được để biết lỗi nào có sẵn và lỗi nào xuất hiện sau khi Agent can thiệp.

  1. Đọc hướng dẫn: mở README.md, SPEC.md và các quy tắc hiện có trước khi ra lệnh.
  2. Kiểm tra trạng thái Git: dùng git status; không trộn thay đổi dở dang của người khác vào nhiệm vụ mới.
  3. Chạy đúng kiểm tra đã có: chỉ chạy lệnh được dự án khai báo, như npm test, npm run build hoặc checklist thủ công trong README.
  4. Lưu bằng chứng ngắn: ghi lại lệnh đã chạy, kết quả và ảnh Preview nếu có. Khi test vốn đã lỗi, tách nó thành việc riêng thay vì quy cho thay đổi mới.
Prompt an toàn: “Chỉ đọc repo. Hãy cho tôi biết trạng thái Git, các lệnh kiểm tra được khai báo và kết quả baseline. Chưa sửa bất kỳ tệp nào.”

Hãy khởi tạo cấu trúc thư mục hoàn chỉnh cho dự án web mới:

4. Tạo file README.md ghi rõ mục tiêu dự án, cách chạy thử nghiệm và cấu trúc thư mục.
📜 Mẫu 2: Tự Động Sinh File Nội Quy Dự Án AGENTS.md Thiết lập "vòng kim cô" cho AI 
Hãy tạo file AGENTS.md tại thư mục gốc của dự án với các quy định nghiêm ngặt sau:
- Vai trò: Bạn là Kỹ sư lập trình Fullstack giàu kinh nghiệm, chuyên về HTML5/CSS/Vanilla JS.
- Quy tắc công nghệ: Không tự ý cài đặt thêm framework bên ngoài (React/Vue/Tailwind) trừ khi tôi yêu cầu. Mọi CSS phải đặt trong file .css riêng, không viết inline style tràn lan.
- Bảo mật: Tuyệt đối không lưu mật khẩu hay API Key ở mã nguồn client.
- Quy trình sửa đổi: Phải phân tích giải pháp và lập kế hoạch (Plan) trước; chỉ sửa đúng file liên quan (Minimal Changes), không xóa hay viết lại mã nguồn đang hoạt động ổn định.
🛡️ Mẫu 3: Đọc Baseline & Kiểm Tra An Toàn Trước Khi Giao Nhiệm Vụ Mới Chống ghi đè mã nguồn 
Chỉ đọc repository. Chưa sửa đổi bất kỳ tệp nào.
Hãy quét toàn bộ cấu trúc dự án và báo cáo cho tôi:
1. Trạng thái Git hiện tại (các file đang staged, modified hoặc untracked).
2. Tóm tắt kiến trúc hiện có và các module đang chạy ổn định.
3. Bản kế hoạch từng bước (Step-by-step Plan) để thực hiện nhiệm vụ [Mô tả tính năng cần làm].
Sau khi tôi duyệt bản kế hoạch này, bạn mới được bắt đầu viết mã.

Hình 3.1: Tổ chức thư mục rõ ràng giúp Agent định vị tệp cần sửa mà không đọc thừa thãi, tiết kiệm Context Window và hạn chế xung đột mã.

2. Bộ ba tài liệu "Định hướng hành vi AI"

Để Agent không đi chệch hướng, hãy luôn duy trì 3 file văn bản ở thư mục gốc:

  1. SPEC.md (Tài liệu đặc tả): Định nghĩa ứng dụng làm gì, ai dùng, các trường dữ liệu và tiêu chí nghiệm thu cụ thể.
  2. AGENTS.md (Quy tắc thực thi): Quy định ngôn ngữ lập trình, thư viện được phép dùng, tiêu chuẩn đặt tên hàm và yêu cầu lập kế hoạch trước khi viết mã.
  3. .gitignore (Bộ lọc an toàn): Danh sách các file và thư mục cấm đẩy lên Git (file chứa API Key, file tạm, thư mục cài đặt nặng).

3. Kỷ luật Git an toàn tuyệt đối khi lập trình cùng AI

  • Tạo nhánh mới cho từng tính năng (Feature Branch): Luôn tạo nhánh mới như git checkout -b feat/user-auth trước khi yêu cầu AI viết mã lớn. Nếu AI làm hỏng, bạn có thể xóa nhánh đi làm lại mà không ảnh hưởng nhánh chính main.
  • Commit theo từng lát cắt nhỏ (Semantic Commits): Commit ngay khi một phần tính năng chạy tốt. Ví dụ: feat: tạo form nhập liệu → feat: kết nối api lưu đơn.
  • Luôn kiểm tra Visual Diff: Không gõ git add . một cách mù quáng. Hãy mở giao diện Diff để xem từng dòng code AI đã sửa đổi.

4. Quản lý biến môi trường (.env) và bảo mật

NGUYÊN TẮC ZERO SECRET LEAKAGE:

Tạo file .env.example chứa các tên biến mẫu (như SUPABASE_URL=your_url_here) để đẩy lên Git, trong khi file .env thật chứa khóa bí mật bắt buộc phải được khai báo trong .gitignore.
